# Skill: 任务合并整理 (Task Merge & Carryover)

## 概述

每日自动完成两件事：

1. **读取昨日未完成任务**（`☐` 开头的行）
2. **读取今日已有任务**（包括已完成的 `☑` 和未完成的 `☐`）

将两组任务一起交给大模型进行**去重合并、语义归类、优先级排序**，然后写入今日面板，形成一份完整、清晰的今日待办清单。

## 数据流

```
昨日切片                            今日切片
┌─────────────────────┐      ┌─────────────────────┐
│ 2026-04-14_work.txt  │      │ 2026-04-15_work.txt  │
│ ☐ 修复登录页Bug     │      │ ☐ 写周报            │
│ ☐ 开会              │      │ ☑ 回复邮件          │
│ ☐ 修复Safari兼容问题 │      └─────────┬───────────┘
└──────────┬──────────┘                 │
           │                            │
           └─────────┬──────────────────┘
                     │ 合并输入 LLM
                     ▼
          ┌──────────────────────┐
          │ 1. 去重合并           │
          │ 2. 语义归类           │
          │ 3. 优先级排序         │
          │ 4. 清晰化重写         │
          │ 5. 剔除今日已完成     │
          └──────────┬───────────┘
                     │ 输出
                     ▼
          ┌──────────────────────┐
          │ work_ai_append.txt    │
          │ → SideNote 渲染为     │
          │   今日待办清单        │
          └──────────────────────┘
```

## 功能规格

### 输入

| 来源 | 文件 | 提取规则 |
|------|------|----------|
| **昨日未完成** | `Daily/{yesterday}_{category}.txt` | 以 `☐` 开头的行（未打勾） |
| **今日已有** | `Daily/{today}_{category}.txt` | `☐` 和 `☑` 开头的行都读取，标记完成状态 |

### 处理 (LLM)

大模型对两组任务进行统一整理：

1. **去重合并** — 昨日和今日中表述不同但语义相同的任务合并为一条
2. **语义归类** — 按语义分组（如：Bug修复 / 功能开发 / 文档沟通 / 运维部署）
3. **优先级排序** — 紧急且重要 > 重要不紧急 > 紧急不重要 > 其他
4. **清晰化重写** — "修复bug" → "修复登录页在 Safari 下的样式兼容性问题"
5. **剔除已完成** — 今日已打勾（☑）的任务，如果昨日也有，说明已经做了，不再列入

### 输出

- **目标文件**: `~/Documents/SideNote_Archive/Current_Week/{category}_ai_append.txt`
- **格式**: 纯文本，每行一条任务，**不带 `☐` 前缀**（SideNote 自动添加）
- **头部注入**: 第一行写入 `--- 昨日遗留 + 今日任务（合并整理）---` 作为标识

## 关键设计决策

### 为什么要读取今日任务？

因为用户可能在 Skill 运行前已经在今日面板中添加了新任务。如果不读取今日任务，就会出现：

```
❌ 错误：不读今日任务 →
   昨日遗留：修复登录页Bug
   今日面板原有：写周报
   → AI 整理后只写了"修复登录页Bug"
   → "写周报"被覆盖丢失了！

✅ 正确：读取今日任务 →
   昨日遗留：修复登录页Bug
   今日已有：[未完成] 写周报
   → AI 合并整理后一起写入
   → 两条任务都在！
```

### 已完成的任务也读取？

是的，读取今日已完成（☑）的任务是为了让 LLM 知道上下文：
- "回复邮件"今天已经做了 → 昨日遗留中如果有"回复客户邮件" → 自动合并 → 知道已完成 → 不再列出
- 避免 AI 机械地把昨日未完成任务全部丢回今日（明明用户今天已经自己处理了）

### 降级策略

LLM 不可用时（无 API Key、网络错误、API 异常），使用**简单合并去重**：
- 今日已完成（☑）的任务跳过
- 今日未完成 + 昨日未完成，按前 10 字去重合并
- 保证不丢任务

## 架构方案

### 方案 A: Python 独立脚本（推荐）

通过 crontab / launchd 每天早上定时执行。

**依赖**: Python 3.10+, `openai` 库

### 方案 B: Swift 内联（集成进 SideNote 应用）

在 `SidePanel.swift` 的 `checkDailyAndAIUpdates()` 中扩展。

**优点**: 用户无感，无需额外部署
**缺点**: 需要在应用内配置 LLM API Key

## 方案 A 详细技术规格 (Python 脚本)

### 文件结构

```
skills/todo_carryover/
├── README.md              # 本文档
├── carryover.py           # 主脚本（可运行）
├── config.json            # 配置文件
├── requirements.txt       # Python 依赖
└── prompts/
    ├── system.md          # LLM 系统提示词
    └── organize.md        # 组织任务的用户提示模板
```

### 命令行参数

| 参数 | 说明 |
|------|------|
| `-c, --category` | 只处理指定分类（work/dev/life） |
| `-d, --date` | 指定昨日日期（默认自动计算昨天） |
| `--today-only` | 只整理今日任务，不处理昨日 |
| `-n, --dry-run` | 预览模式，不实际写入 |
| `-v, --verbose` | 详细输出原始任务内容 |

### 使用示例

```bash
# 正常执行（处理所有分类）
python3 carryover.py

# 只处理工作分类
python3 carryover.py -c work

# 预览模式（不写入）
python3 carryover.py --dry-run

# 带 API Key 执行
SIDENOTE_LLM_API_KEY="sk-xxx" python3 carryover.py

# 只整理今日任务
python3 carryover.py --today-only

# 指定昨日日期（测试用）
python3 carryover.py -d 2026-04-14
```

### LLM 提示词设计

**System Prompt** (prompts/system.md):

```
你是一个待办事项整理助手。你会收到两类任务：

A. 昨天未完成的任务（需要延续到今天）
B. 今天已有的任务（部分已完成、部分未完成）

请执行：
1. 去重合并 — 将 A 和 B 中语义相同的任务合并
2. 语义归类 — 将松散任务分组（用【分组名】做标题）
3. 优先级排序 — 紧急且重要 > 重要不紧急 > 紧急不重要 > 其他
4. 清晰化重写 — 模糊任务改写为可执行的形式

特别注意：
- 今天【已完成】的任务不要再次列入
- 整理后的列表应该是「今天还需要做的事情」
- 合理判断优先级，不要机械保留所有任务

输出规则：
- 只输出任务文本本身，每行一条
- 分组标题用【】包裹，独占一行
- 不要编号，不要项目符号
- 不要 ☐ 符号
- 不要任何 AI 说明
```

## 边缘情况处理

| 场景 | 行为 |
|------|------|
| 昨日无记录文件 | 只处理今日任务 |
| 今日无记录文件 | 只处理昨日遗留任务 |
| 两日都无任务 | 静默跳过该分类 |
| 昨日任务今日已全部完成 | 从昨日带走已完成上下文，但不重复列出 |
| LLM API 调用失败 | 降级为简单合并去重（已完成的剔除） |
| API Key 未配置 | 同上降级策略 |
| 周一执行 | 读取上周五的存档（从备份目录读取） |
| 跨周执行（周目录已切换） | 从上周备份目录读取 |
| `--today-only` 模式 | 跳过昨日读取，只整理今日任务 |

## 安装与部署

### 1. 安装依赖

```bash
cd skills/todo_carryover
pip install -r requirements.txt
```

### 2. 配置环境变量

```bash
echo 'export SIDENOTE_LLM_API_KEY="sk-your-api-key"' >> ~/.zshrc
source ~/.zshrc
```

### 3. 设置 crontab（每天早上 8:00 执行）

```bash
crontab -e
# 添加：
0 8 * * * cd /path/to/skills/todo_carryover && python3 carryover.py >> carryover.log 2>&1
```

## 效果示例

### 昨日文件 (2026-04-14_work.txt)
```
☐ 修复登录页Bug
☐ 开会
☐ 修复登录页Safari兼容问题
☐ 写周报
```

### 今日文件 (2026-04-15_work.txt)
```
☑ 回复邮件
☐ 完成Q2汇报PPT
```

### LLM 合并整理后写入 Inbox
```
--- 昨日遗留 + 今日任务（合并整理）---
【Bug修复】
修复登录页在 Safari 下的样式兼容性问题
【文档】
完成本周工作周报编写
完成Q2汇报PPT制作
【会议】
整理周会待办事项并同步团队
```

> "回复邮件"不在列表中 → 因为今日已打勾完成，AI 自动剔除。
> "修复登录页Bug"和"修复Safari兼容问题" → 合并为一条。

### SideNote 渲染效果

用户打开面板，看到的是**合并去重后、按优先级排序**的今日待办清单，每条前有 `☐` 可直接勾选。
